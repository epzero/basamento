# Schema: JSON Schema and canonical JSON

Status: **Implemented** (WP-L2-02, `core/schema`). Design: [`design.md`](design.md);
users: ADR-0003 and `docs/architecture/flow-engine.md` (state and gate schemas,
the IR content hash), ADR-0006 and `docs/architecture/model-layer.md`
(parameter schemas, structured output). Type-checking CEL against a schema
belongs to `specs/expr` (WP-L2-01).

## Generation from Go types

### REQ-SCHEMA-001 — One property per encoded field
When a schema is generated from a Go struct type, the schema generator shall describe the struct as an object with one property for each field that `encoding/json` encodes, named as `encoding/json` names it.

### REQ-SCHEMA-002 — Property types follow Go types
When a schema is generated from a Go struct type, the schema generator shall give each property the schema of its Go field type: strings as `string`, integer kinds as `integer`, floating-point kinds as `number`, `bool` as `boolean`, arrays as `array` of the element schema, slices as `null` or an `array` of the element schema, maps with string keys as `null` or an `object` whose values use the element schema, and structs as nested objects generated by the same rules, except where `REQ-SCHEMA-038` to `REQ-SCHEMA-048` give the property a different schema.

### REQ-SCHEMA-003 — Required fields
When a schema is generated from a Go struct type, the schema generator shall list as required every property whose field has neither the `omitempty` nor the `omitzero` option.

### REQ-SCHEMA-004 — Closed objects
When a schema is generated from a Go struct type, the schema generator shall disallow properties other than those of the struct.

### REQ-SCHEMA-005 — Descriptions from tags
Where a struct field has a `jsonschema` tag, the schema generator shall use the tag's text as the description of the field's property.

### REQ-SCHEMA-006 — Types without a JSON form
If a Go type contains a field whose type has no JSON form (a channel, a function or a complex number), then the schema generator shall reject the type with code `invalid_argument`, naming the path of that field.

### REQ-SCHEMA-007 — Stable generation
The schema generator shall produce the same canonical form every time it generates a schema from the same Go type.

### REQ-SCHEMA-008 — Encoded values conform
When a value of a Go type is encoded with `encoding/json`, the schema validator shall accept the result against the schema generated from that type, whether the encoded value is the type itself, a struct that embeds the type, or a struct with a field of the type.

## Bytes, raw JSON and types with their own encoding

### REQ-SCHEMA-038 — Byte slices are base64 strings
When a schema is generated from a Go struct type, the schema generator shall give a field of type `[]byte`, or of a named type whose underlying type is `[]byte` and whose method set and whose pointer's method set include neither `encoding.TextMarshaler` nor `json.Marshaler`, the schema of a nullable string with `contentEncoding` `"base64"`, admitting `null` and any string and nothing else.

### REQ-SCHEMA-039 — Raw JSON admits any value
When a schema is generated from a Go struct type, the schema generator shall give a field of type `json.RawMessage` a schema that admits every JSON value, including `null`.

### REQ-SCHEMA-040 — Fixed byte arrays are integer arrays
When a schema is generated from a Go struct type, the schema generator shall give a field whose type is an array of bytes whose method set and whose pointer's method set include neither `encoding.TextMarshaler` nor `json.Marshaler` the schema of an array of exactly its length in integers, admitting neither `null` nor strings.

### REQ-SCHEMA-041 — Text encoding is a string
When a schema is generated from a Go type, the schema generator shall describe as a string every value whose type's method set includes `encoding.TextMarshaler` and does not include `json.Marshaler`, wherever that type appears: as a struct field, an array or slice element, a map value, or the type itself.

### REQ-SCHEMA-042 — JSON encoding admits any value
When a schema is generated from a Go type, the schema generator shall describe as a schema that admits every JSON value every value whose type's method set includes `json.Marshaler`, except the types of `REQ-SCHEMA-039`, `REQ-SCHEMA-043` and `REQ-SCHEMA-044`, wherever that type appears: as a struct field, an array or slice element, a map value, or the type itself.

### REQ-SCHEMA-043 — time.Time is a string
When a schema is generated from a Go type, the schema generator shall describe `time.Time` as a string.

### REQ-SCHEMA-044 — json.Number is a number
When a schema is generated from a Go type, the schema generator shall describe `json.Number` as a number.

### REQ-SCHEMA-045 — An encoding that only the pointer has
If a type's method set includes neither `encoding.TextMarshaler` nor `json.Marshaler` but the method set of the pointer to that type includes one of them, then the schema generator shall describe every value of that type as a schema that admits every JSON value, wherever it appears: as a struct field, an array or slice element, a map value, or the type itself.

## The string tag option

### REQ-SCHEMA-046 — The string option on numbers and booleans
When a struct field's `json` tag has the `string` option and the field's type, after following pointers, is an integer, floating-point or boolean type, or is `json.Number`, the schema generator shall give the property the schema of a string that holds exactly the JSON literal `encoding/json` writes for a value of that type, admitting `null` as well when the field is a pointer.

### REQ-SCHEMA-047 — The string option on strings
When a struct field's `json` tag has the `string` option and the field's type, after following pointers, is a string type other than `json.Number`, the schema generator shall give the property the schema of a string that holds exactly the quoted JSON string `encoding/json` writes for the field's value, admitting `null` as well when the field is a pointer.

## Map keys

### REQ-SCHEMA-048 — Map keys encoding/json writes as strings
When a schema is generated from a Go struct type, the schema generator shall give a map whose key type has a string kind, an integer or unsigned integer kind (including `uintptr`), or a method set that includes `encoding.TextMarshaler` the schema of `null` or an `object` whose values use the element schema.

### REQ-SCHEMA-049 — Map keys encoding/json cannot write
If a map's key type has neither a string kind nor an integer or unsigned integer kind and its method set does not include `encoding.TextMarshaler`, then the schema generator shall reject the type with code `invalid_argument`, naming the path of the field that holds the map and the key type.

## Compiling schemas

### REQ-SCHEMA-010 — Default dialect
The schema compiler shall interpret a schema that declares no `$schema` as JSON Schema draft 2020-12.

### REQ-SCHEMA-011 — Invalid schemas
If a schema does not satisfy the meta-schema of its dialect, then the schema compiler shall reject it with code `invalid_argument`, naming the location in the schema of each violation.

### REQ-SCHEMA-012 — No fetching of references
If a schema refers to a schema that is not in its schema set, then the schema compiler shall reject it with code `invalid_argument`, naming the reference, without fetching the reference from the network or the file system.

### REQ-SCHEMA-013 — References within a schema set
When a schema refers to another schema of its schema set by that schema's id, the schema compiler shall resolve the reference to that schema.

## Validation

### REQ-SCHEMA-020 — Violations with locations
If an instance does not satisfy a schema, then the schema validator shall reject it with code `invalid_argument`, listing each violation with its instance location and the keyword that failed.

### REQ-SCHEMA-021 — Location of a missing or disallowed property
When a violation is a required property that is missing or a property that is not allowed, the schema validator shall report the instance location of that property.

### REQ-SCHEMA-022 — Deterministic order of violations
The schema validator shall list violations ordered by instance location and then by keyword, both compared byte by byte.

### REQ-SCHEMA-023 — Exact numbers
The schema validator shall compare numbers by their exact decimal value, never by a binary floating-point approximation.

### REQ-SCHEMA-024 — Asserted formats
If a string does not match its `format` and the format is one of `date-time`, `date`, `time`, `duration`, `email`, `uri` or `uuid`, then the schema validator shall report a violation of keyword `format` at the string's instance location.

### REQ-SCHEMA-025 — Duplicate names in instances
If an instance contains an object with two members of the same name, then the schema validator shall reject it with code `invalid_argument` at the instance location of the second member.

### REQ-SCHEMA-026 — Other formats are annotations
Where a schema uses a `format` other than those of REQ-SCHEMA-024, the schema validator shall accept any string for it.

## Canonical JSON

### REQ-SCHEMA-030 — Canonical layout
The canonicalizer shall write the canonical form of a JSON value as defined by RFC 8785: no insignificant whitespace, object members ordered by the UTF-16 code units of their names, and array elements in their original order.

### REQ-SCHEMA-031 — Canonical numbers
The canonicalizer shall write each number as RFC 8785 writes it: the shortest form that reads back to the same IEEE 754 double, in ECMAScript notation.

### REQ-SCHEMA-032 — Canonical strings
The canonicalizer shall write each string as RFC 8785 writes it: UTF-8, escaping only the quotation mark, the reverse solidus and control characters, with the short escapes `\b`, `\t`, `\n`, `\f`, `\r` where they exist and `\u00xx` in lowercase hexadecimal otherwise.

### REQ-SCHEMA-033 — Equal values, equal bytes
When two JSON texts denote the same value, the canonicalizer shall produce the same bytes for both.

### REQ-SCHEMA-034 — Idempotence
When the canonicalizer is given a canonical form, the canonicalizer shall return it unchanged.

### REQ-SCHEMA-035 — Numbers that would change value
If a JSON text contains a number that overflows IEEE 754 double or whose value differs from the value of its canonical form, then the canonicalizer shall reject the text with code `invalid_argument` at the instance location of that number.

### REQ-SCHEMA-036 — Duplicate names
If a JSON text contains an object with two members of the same name, then the canonicalizer shall reject the text with code `invalid_argument` at the instance location of the second member.

### REQ-SCHEMA-037 — Invalid Unicode
If a JSON text contains a string with an unpaired surrogate escape, then the canonicalizer shall reject the text with code `invalid_argument` at the instance location of that string.
